# React コーディングテスト

レストランのメニューと注文を扱う小さなアプリを作ってください。
`src/data.ts` の `MENU` を使います(データ自体は編集しないでください)。

## 準備(テスト開始前に済ませておいてください)

- Node.js 20 以上が必要です(`node -v` で確認)。
- このフォルダで次を実行します。

```bash
npm install
npm run dev
```

- ターミナルに表示される URL(通常は `http://localhost:5173`)をブラウザで開きます。
- ファイルを保存するとブラウザに自動で反映されます(ページの再読み込みは不要です)。
- エディタは普段お使いのもの(VS Code など)で構いません。

## ルール

- 制限時間は 60 分です。全部終わらなくても大丈夫です。できたところまでで評価します。
- ステップ 1 から順番に進めてください。
- 考えていることを声に出しながら進めてください。
- [react.dev](https://react.dev/learn) と [MDN](https://developer.mozilla.org/ja/) のドキュメントは見て構いません。AI ツールの使用(エディタの AI 補完を含む)とコードのコピペ検索は禁止です。
- ヒント:データの絞り込みや変換には、JavaScript の配列メソッド(`map`、`filter`、`sort`、`reduce` など)が役に立ちます。
- コンポーネントの追加やファイル分割は自由です。
- スタイルは評価しません。見た目は最低限で構いません。
- 仕様で迷ったら、自分で決めずに質問してください。

## ステップ 1:メニューを表示する

- メニューをカテゴリ別に分けて表示してください。カテゴリ名を見出しとして表示し、その下にそのカテゴリの品目を並べます。
- カテゴリの表示順は `MENU` に最初に登場する順(前菜 → メイン → デザート → ドリンク)にしてください。
- カテゴリ名はコードに直接書かず、`MENU` のデータから求めてください(データに新しいカテゴリが追加されても、コードを変えずに表示されるようにします)。
- 見出しには、そのカテゴリの品目数を `メイン (5)` の形式で添えてください。
- 各カテゴリの中では、品目を**価格の安い順**に並べてください。価格が同じ場合は `MENU` の順のままで構いません。
  - `MENU` 自体を並べ替えて書き換えないでください。
- 各品目には名前と価格を `ティラミス ¥580` の形式で表示してください。
- `tags` がある品目は、価格の後ろにタグを `[ベジ] [辛い]` のように並べてください。`tags` が空のときは何も表示しません。
- 売り切れの品目(`soldOut: true`)は、名前の後ろに `(売り切れ)` を付けて、行全体をグレーで表示してください。

表示イメージ:

```
前菜 (3)
  フライドポテト(売り切れ) ¥480 [ベジ]   ← グレー
  シーザーサラダ ¥680 [ベジ]
  生ハムとメロン ¥880
メイン (5)
  チキンカレー ¥980 [辛い]
  ペンネアラビアータ ¥1180 [ベジ] [辛い]
  マルゲリータ ¥1280 [ベジ]
  ...
デザート (2)
  ...
ドリンク (3)
  コーヒー ¥380 [ベジ]
  オレンジジュース ¥420 [ベジ]
  ジンジャーエール ¥420 [ベジ] [辛い]
```

## ステップ 2:検索と絞り込み

- メニューの上に、検索ボックス・セレクトボックス・チェックボックスの 3 つを置いてください。
  - 検索ボックスのプレースホルダーは `メニュー名で検索`
  - セレクトボックスの選択肢は `すべて` / `¥500以下` / `¥1000以下`(初期値は `すべて`)
  - チェックボックスのラベルは `ベジ対応のみ表示`(初期状態はオフ)
- 検索は品目名の**部分一致**です。入力の前後の空白は無視してください。ひらがな・カタカナの区別などは考えなくて構いません。
- 検索ボックスが空のときは、検索条件なしとして扱います。
- セレクトボックスで `¥500以下` を選ぶと価格が 500 円以下の品目だけ、`¥1000以下` を選ぶと 1000 円以下の品目だけを表示します。
- チェックボックスがオンのときは、`tags` に `ベジ` を含む品目だけを表示します。
- 3 つの条件を**すべて満たす**品目だけを表示します。
- 見出しの `(数)` は、絞り込み後に表示している品目数にしてください。
- 表示する品目が 1 つもないカテゴリは、カテゴリの見出しごと表示しないでください。
- 全カテゴリで表示する品目がないときは、一覧の代わりに `該当するメニューがありません` と表示してください。

例:検索ボックスに「ー」と入力し、`¥1000以下` を選び、`ベジ対応のみ表示` をオンにした場合

```
前菜 (1)
  シーザーサラダ ¥680 [ベジ]
デザート (1)
  ジェラート(売り切れ) ¥480 [ベジ]   ← グレー
ドリンク (2)
  コーヒー ¥380 [ベジ]
  ジンジャーエール ¥420 [ベジ] [辛い]
```

(ビーフステーキ・サーモンのムニエルは価格とタグの条件に合わない。売り切れの品目も条件に合えば表示する)

## ステップ 3:注文

### 一覧側

- 売り切れでない品目の右に `注文する` ボタンを表示してください。
- 売り切れの品目には、ボタンを表示しないでください。

### 注文側

- メニューの下に `注文内容` という見出しを付けて、注文の一覧を表示してください。
- 注文の各行は `ティラミス ×2 ¥1160 [+] [−] [削除]` の形式です。
  - `¥1160` はその行の小計(価格 × 数量)です。
- 行の並び順は、初めて注文した順です。
- 同じ品目をもう一度 `注文する` したら、行を増やさずに数量を 1 増やしてください。
- `+` で数量を 1 増やし、`−` で 1 減らします。数量が 0 になったら、その行を削除します。
- `削除` で、数量に関係なくその行を削除します。
- 一覧の最後に、次の 2 行を表示してください。
  - `小計 ¥xxx`(全行の小計の合計)
  - `合計(税込) ¥xxx`(小計の 10% 増し。小数点以下は切り捨て)
- 一覧の下に `注文をクリア` ボタンを置き、押すと全行を削除してください。
- 注文が空のときは、行・小計・合計・`注文をクリア` の代わりに `まだ注文がありません` と表示してください。
- 検索や絞り込みで一覧から品目が見えなくなっても、注文の中身はそのまま表示してください。
- 数量の上限は考えなくて構いません(いくつでも注文できます)。

表示イメージ:

```
注文内容
  ティラミス ×2 ¥1160 [+] [−] [削除]
  コーヒー ×1 ¥380 [+] [−] [削除]
  小計 ¥1540
  合計(税込) ¥1694
  [注文をクリア]
```

## ステップ 4:ヘッダー

- ページの一番上にヘッダーを作り、`注文 (3点) ¥1694` のように注文の品目数と税込合計を表示してください。
  - 品目数は**数量の合計**です(行数ではありません)。例:ティラミス ×2、コーヒー ×1 なら `3点`
  - 注文が空のときは `注文 (0点) ¥0` と表示します。
- `Header` と `Order`(注文内容)は、それぞれ別のコンポーネントにしてください。
- `App` から `Header` や `Order` へ、注文のデータや更新用の関数を props で渡さないでください。それぞれのコンポーネントが直接注文のデータを参照できるようにしてください。
- 注文を変更する処理(追加・増やす・減らす・削除・クリア)は 1 か所にまとめてください。ボタンを押したコンポーネント側は「何をしたいか」(例:ティラミスを追加したい)だけを伝え、配列の具体的な更新方法は知らなくてよい形にしてください。
- 品目数や合計は state として別に持たず、注文の配列から計算してください。

## ステップ 5:使い勝手の改善

### 自動フォーカス

- ページを開いたとき、検索ボックスに自動でフォーカスが当たるようにしてください。
- HTML の `autoFocus` 属性は使わずに実装してください。

### 検索の遅延反映

- 検索ボックスに入力した文字は、入力欄にはすぐ表示されます。
- 一覧の絞り込みは、**入力が止まってから 400ms 後**に反映してください。
  - 400ms 以内に続けて入力した場合は、最後の入力から改めて 400ms 待ちます。
  - 例:「カ」「レ」「ー」を素早く入力したら、絞り込みは「カレー」で 1 回だけ行われます。
- 待っている間(入力欄の文字と、絞り込みに使っている文字が違う間)は、検索ボックスの横に `絞り込み中…` と表示してください。反映されたら消します。
- セレクトボックスとチェックボックスは、遅延させずにすぐ反映してください。
- この「値の変化を一定時間遅らせる」処理は、別ファイルに切り出し、他のコンポーネントからも同じように使える形にしてください。
- 入力の途中でコンポーネントが画面から消えた場合でも、待機中の処理が残らないようにしてください。

## ボーナス(時間が余ったら)

- 注文の内容を `localStorage` に保存し、ページを再読み込みしても注文が残るようにしてください。
- 保存するキーは `order` とします。
- 保存されたデータが壊れていても(例:`localStorage` に `order` として `{{{` が入っていても)、アプリが落ちずに空の注文として開始できるようにしてください。
